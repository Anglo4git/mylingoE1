### Real-kill candidate confirmed (reasoning verified against an existing test, not mutation-tested)
- `calculateNextIntervalHours`'s `prior <= 0` clause (in `if (!Number.isFinite(prior) || prior <= 0) prior = (Number(previous && previous.interval_days) || 0) * 24;`) is directly pinned by an existing test: `calculateNextIntervalHours({ interval_hours: 0, interval_days: 4, consecutive_successes: 1 }, 85)` must equal `192` — `interval_hours: 0` is finite but `<= 0`, so without the `prior <= 0` half of the guard, the legacy `interval_days` fallback would never trigger and the result would differ. **Do not re-try.**
