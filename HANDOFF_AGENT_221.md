### 3 new equivalents confirmed — two condition-subsumption guards, one whole-function tautology (a new, larger-scale class)

| Location | Mutation tried | Result | Why it's equivalent |
|---|---|---|---|
| `recommendationForSkill` (~101) | Changed `if (availableLevels && Array.isArray(availableLevels) && availableLevels.length) {` to `if (Array.isArray(availableLevels) && availableLevels.length) {`, dropping the leading `availableLevels &&` | **953 passed, 1 failed (identity only) → equivalent** | `Array.isArray(x)` is `false` for every non-array value, including every falsy one (`undefined`, `null`, `0`, `''`, `false`, `NaN`) — there is no falsy value for which `Array.isArray` returns `true`. So the leading truthy check can never block anything that `Array.isArray` wouldn't already block, for any possible input. **Sub-pattern: a truthy pre-check fully subsumed by a stricter type check later in the same `&&` chain — distinct from Class B (redundant-because-of-an-earlier-branch) since this is redundancy within a single condition, not across branches.** |
| `validLevel` (~62) | Changed `level = String(level == null ? '' : level).toLowerCase();` to `level = String(level).toLowerCase();`, dropping the `level == null ? '' : ...` ternary | **953 passed, 1 failed (identity only) → equivalent** | The ternary exists to avoid `String(null) === 'null'` / `String(undefined) === 'undefined'` leaking through, by substituting `''` first. But `LEVELS.indexOf('null')` and `LEVELS.indexOf('undefined')` are both `-1` anyway — neither string is a real CEFR code — so the substitution changes the intermediate string but not the final `-1`-vs-found outcome for any input. Same class as the `recommendationForSkill` finding above: a guard that changes an intermediate value without ever changing what the final membership check reports. |
| `validateProfile` (~202–209) | Replaced the entire `.every(...)` body — checking `SKILLS.indexOf(item.skill) >= 0 && LEVELS.indexOf(item.level) >= 0 && Number.isFinite(item.score) && item.question_count >= RULES.min_reported_questions` — with a bare `return true;` (keeping the `recommendSkillLevels(...)` call for any side-effect parity) | **953 passed, 1 failed (identity only) → equivalent** | Traced why: every item `recommendSkillLevels` returns was already built by `recommendationForSkill`, which (a) only returns non-null for `skill` values passing `SKILLS.indexOf(skill) >= 0`, (b) only returns a `level` that is either `normalizeLevel`'s output (always in `LEVELS`) or one of the `availableLevels`-filtered candidates (also always in `LEVELS`, or the function returns `null` before ever reaching `return {...}`), (c) only reaches the `return {...}` after `numericScore` + `clamp` guarantee `score` is a finite number, and (d) is only pushed into `items` in `recommendSkillLevels` after the `count < RULES.min_reported_questions` early-return already excluded low counts.
