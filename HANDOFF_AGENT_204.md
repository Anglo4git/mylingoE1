## Bugs found + fixed

### runtime-v2-adapter.js
1. Text fields (`question`, `category`, `explanation`, quiz `title`/`description`/`brand`, etc.): `String(x)` turned an object into the learner-visible text `"[object Object]"`, an array into `"a,b"`, `true` into `"true"`, and **threw** for an object carrying its own non-function `toString` (`JSON.parse('{"toString":1}')`). Only strings (trimmed) and finite numbers (stringified) are text now; everything else is `''`.
2. `tags`: same `String()` problem. An authored array of tags (`['a','b']`) now joins into `"a,b"` on purpose; junk items inside the array are dropped.
3. Numbers (`version`, question-count, etc.): `Number(true)` / `Number(false)` / `Number([])` / `Number([5])` / `Number(' ')` are `1`/`0`/`0`/`5`/`0`, so `version: true`, `correct_index: false` (read as `0`), or `questions: [3]` were silently accepted as valid numbers. Only a real number or a non-blank numeric string counts now.
4. `question_type` / `activity_type`: a bare `QUESTION_TYPE_ALIASES[type]` lookup also resolves inherited names, so `question_type: "__proto__"` or `"constructor"` returned `Object.prototype` / the `Object` function instead of a string. Now an own-property lookup, and a junk/blank type falls to the caller's real default (`radio` for questions, `quiz` for activities) instead of always defaulting through the loose `stringValue(value || 'radio')` path.
5. `correctIndex` alias resolution: the first alias holding a real integer now wins — previously a junk value under an earlier alias (`correctIndex: "x"`) hid a valid later one (`correct_index: 2`).
6. `acceptedAnswers`: a raw object/array item (from the option-object `answers[]` fallback, or a junk `acceptedAnswers` entry) used to become the accepted text `"[object Object]"`, and a `null` item became the text `"null"`. Strings, booleans and finite numbers are kept as authored; an object contributes its `text`/`label`/`value`; everything else is dropped.
7. Media (`imageUrl`/`audioUrl`, `media.image`/`media.audio`): a source had to be a **string** — a number, object, or blank string is not a URL. The first non-blank string of `src`/`url` wins (previously a junk `src` hid a valid `url`).
8. Hierarchy ids (`course.id`, `unit.id`, `lesson.id`, `activity.id`, and their `_id` aliases): the first non-blank id now wins, and id `0` is a real id (previously `id: 0 || id: 'unit-1'` fell straight to the generated fallback because `0` is falsy).

### canonical-metadata.js
9. `skill`/`category`/`subskill`/`cefr`/`objective`/`learning_objective`: same `String()` problem as above — an object, array, boolean, number, or own-`toString` object could give a category like `["grammar"]` a skill via `String()` → `"grammar"`, or throw. Now text fields are real strings only.
10. `difficulty`/`estimated_time_seconds`: `Number(true)` / `Number('')` / `Number(' ')` / `Number([3])` are `1`/`0`/`0`/`3`, so junk values used to pass through as `1`, `0`, or a wrong number. Only a real finite number or a non-blank numeric string is kept now.

### offline-packs.js
11. `readMeta`: a stored meta blob that was `null`/an array/a number/a string/unparseable JSON made `touch()` **throw** (setting a property on a non-object), which rolled `installPack` back to nothing installed and made `isInstalled` report every pack as not installed. `readMeta` now always returns a prototype-free map containing only its own finite-number entries; junk keys and junk values are dropped, reserved names (`constructor`, `__proto__`, `toString`) are ordinary keys.
12. `getIndex`: the fetched body must now be a real object (not `null`/array/number/string) or it rejects with `Invalid offline pack index` before anything downloads.
13. `findPack`: only a string or number `pack.id` matches (an object id used to match via `String()` → `"[object Object]"`, and threw for an own-`toString` object); junk entries are skipped rather than crashing the search.
14. Pack `files`: every entry must now be a non-blank string that resolves inside the app's own origin. Previously a `null`/object entry became the relative URL `"null"`/`"[object Object]"`, and an absolute or protocol-relative entry (`//evil.example/...`, `https://evil.example/...`) let the installer fetch and cache assets from another origin. An invalid file list now makes `installPack` reject with `Invalid offline pack: <id>` before any download, and such a pack is never reported `isInstalled`.
15. `isInstalled`: a dependency cycle (or a pack depending on itself) previously **recursed without end**, re-fetching `packs.json` each time. It now carries a per-branch visited-set (a diamond dependency shared by two branches still resolves fine) and returns `false` for any id already on its own branch's stack.
16. `dependencies`: junk entries (`null`, objects, booleans, nested arrays) are now ignored; a numeric dependency id is treated as its string form, matching `findPack`.
17. Cache eviction (`cleanupOldCacheVersions`'s installed-pack trim): the pack being installed and its whole dependency chain are protected from eviction even when they hold the oldest stored timestamps (this logic already existed in Agent 202/203-era code but had no direct test; it is now directly covered and confirmed correct — no bug here, but it was one plausible-looking mutation survivor that turned out to be a real behavior worth pinning).
18. Removed `cacheFor`, a dead unused function left over from an earlier version of the module.

### offline-packs-ui.js
19. `esc`: `String(x)` on the pack `label`/`level` (rendered into the panel) turned an object into `"[object Object]"` and **threw** for an own-`toString` object — inside the render chain this replaced the whole panel with the "could not be loaded" note for every pack, not just the bad one. `esc` now accepts only strings/numbers as text.
20. Panel pack list: one malformed entry (`null`, a number, no usable `id`, a blank/object/boolean `id`) previously crashed the entire render instead of just being skipped. The list is now filtered to entries with a real string/number id before rendering.
21. Pack `label` display: fell back to `esc(pack.label || pack.id)`, so a non-blank-but-junk label (an object) rendered as `""` even though a usable fallback (`pack.id`) existed. Now falls back to `pack.id` whenever `label` is not real non-blank text.
22. Pack `level` suffix: a junk `level` value (object/array/boolean) rendered a dangling `" · "` with nothing after it. Now the separator only appears when the escaped level text is non-empty.
